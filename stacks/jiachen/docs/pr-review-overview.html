MCODE REVIEW

PR review that has to prove its findings

The same rules run in your agent and in CI. A second pass tries to refute every blocker, a script — not a model — decides the verdict, every finding is a thread people can answer, and the reviewer tunes itself on your own history.

SHARED RULES

One rule set, two places it runs
  • Severity P0–P3 with real examples
  • Evidence ladder: no file:line, no finding; blocking needs a traced failure
  • 6 review directions: behavior, contracts, security, cross-feature, duplication, general
  • Your repo’s rules: .mcode-review.json risk paths, .mcode-review.md known pitfalls
Read from the merge base in CI, so a PR can’t rewrite the rules that review it.
